# 参考驱动的逻辑图设计

用户指定的参考决定视觉语言。按实际来源记录用途和证据，可使用白底、彩色、几何、插画等任意组合。严肃、创意可以描述观感，选型依赖来源里看得见的特征和本页要说清的关系。

## 从参考提取可用的手法

对代表性页面或区域观察以下特征。记录页码、图号或网页视口，将观察和延展分别写入设计包的证据与规则。

| 观察维度 | 记录什么 | 能影响的决定 |
| --- | --- | --- |
| 阅读次序和主焦点 | 标题与图的位置、先看哪项、解释和证据的距离 | 图示的入口、对齐轴和强调位置 |
| 轮廓和路径 | 开放／围合、硬边／圆弧、直线／折线／曲线、箭头位置 | 选择轨道、环、分组、曲线或直线 |
| 布局与密度 | 重复轴、标题层级、条带、连续留白、标签长度与行数 | 横纵构图、节点尺寸和溢出后的备选 |
| 用色与层次 | 背景色、分区色、文字色、承担重点的强调色 | 各图层的颜色角色和对比度 |
| 适用范围 | 观察发生在章节页、数据图、概念图，还是第三方商标或配图 | 主参考中哪些规则可跨页，哪些仅能限于样本 |

文稿决定数据、方向、归属和数量。比如参考有上升曲线，但新稿只表达无量值的顺序，可以借用连线形态或色彩节奏，保留水平参考轴。两个轴只有高低分类时用定性矩阵。若须呈现真实坐标，选带可核对尺度的图表。

## 公开报告可借鉴的结构

外部案例为结构备选。记录案例出处与适用条件。默认用当前参考的几何、文字、构图和颜色呈现新稿。用户指定外部报告为主参考时，按同样方法提取其可观察风格。出现来源冲突时，以用户指定的作用域为准。

| 参考图示 | 可复用手法 | 使用条件与边界 |
| --- | --- | --- |
| [McKinsey Government Leaders Forum，幻灯片 8](https://www.mckinsey.com/~/media/mckinsey/industries/public%20and%20social%20sector/mckinsey%20center%20for%20government/government%20leaders%20forum%202023/mckinsey_glf2023_transforming-technology-in-government.pdf#page=8) | 先出现阶段转折，再按共同维度逐行对照 | 两个状态必须沿同一维度比较。定性差异可使用定性字段。文稿明确是转型阶段时可以加方向。 |
| [McKinsey Rewired，Exhibit 2](https://www.mckinsey.com/capabilities/tech-and-ai/our-insights/rewired-to-outcompete) | 大类、子能力和解释对齐成三列 | 适合存在归属与分组的能力图谱。列表编号主要给读者定位，文稿另有顺序时才使用推进箭头。 |
| [BCG Your Revenue Strategy，Exhibit 2](https://www.bcg.com/publications/2024/your-revenue-strategy-depends-on-your-starting-point) | 四象限中可有不同数量的说明项，色面用于强调选定象限，旁边保留样本口径 | 轴、方向、分类标准齐全时使用；分类与定量坐标区分。数字必须可追至输入。 |
| [BCG The Future of Finance，Exhibit 22](https://web-assets.bcg.com/2b/ee/c291f4164652a867da2c20c290eb/the-future-of-finance-2025-fit-for-growth-built-for-purpose.pdf) | 把概念分层、所占比重和实施能力放在同一阅读方向 | 借用逻辑时保持源稿层级。用面积或比例编码时，需要新稿有对应数据与口径。 |
| [Microsoft SmartArt 原厂目录](https://support.microsoft.com/en-us/office/graphics-visuals/all-smartart-graphics-described) | 用关系导航，逐款写清文字层级与适用容量 | 用真实槽位和成片核对可见内容，超过容量选择另一画法或拆分。 |

## 制作与复验

1. 先试原包严格匹配，保留缺口。使用同样的文稿复用参考已具备的视觉特征。出现缺口时将引入的构图标为延展，并区分来源中观察到的规则与新稿补出的画法。
2. 按关系选画法与容量。可先用库里的同维度状态对照或定性矩阵，较长文案、更多维度或同象限多个条目需要另外做密度变体。确认阶段、分组与共同维度后再决定箭头与容器。时间段图保持一致时间轴与条长。
3. 对照真实页面，核对参考哪些做法落到了成稿中的哪片区域，以及反向调整是否改变内容关系。优先验收节点、方向、轴、容量、数字和可编辑性。条件允许时对照两个成片来判断选用哪种表达。

## 多层归属与跨角色交接

先写出读者要回答的问题，再比较能保留同一批事实的画法。原包报告归属或交接缺口时，可在制作副本中试以下构图。

| 读者问题 | 优先试的画法 | 保留的关系与边界 |
| --- | --- | --- |
| 谁直接向谁汇报？ | 连线树 | 每一段父子归属有明确端点。兼任或跨组关系单独标注。 |
| 每组由哪些岗位组成？ | 嵌套容器 | 外层是共同范围，内层是独占分组。组名与成员都可读，组间留白清楚。存在多归属时改用有标签的连接或分组表。 |
| 查某个组的下属职责 | 分组表 | 分组与下属沿共同基线对齐，必要时为职责预留一列。 |
| 谁把什么交给谁？ | 泳道 | 每个动作放在对应的阶段和角色内。箭头的起点、终点与交接物明确。上下方向由实际发送方决定。无交接证据的格子只呈现动作。 |
| 每个阶段各角色分别做什么？ | 阶段 × 角色表 | 两个维度共用阅读轴。需要保留交接时，明确写出阶段、发送方、接收方和交接物。 |
| 用户可见的体验靠哪些后台动作支持？ | 服务蓝图 | 在同一阶段对齐用户、前台、后台和支持系统。依据文稿标出可见性，其余依赖按原稿证据补充。 |

对照时固定文案和参考视觉参数，测试能否从成片复述直属归属、交接对象和可见性。换参考后复查分区、线与文字的对比度，再测试长标签与紧凑构图。[嵌套容器和泳道](structural-components.md#嵌套容器与泳道的配方绑定)已通过社区旧照片和校园仪器共享两份模拟稿的成片复核。换稿时按原文重新确认发送方、接收方与交接物。按本页实测字宽、行数、箭头空间和实际版位设定容量，超限时可用角色表或拆页。

可复用的参考切入点包括 [IBM 的嵌套与边界指导](https://www.ibm.com/design/language/infographics/technical-diagrams/usage/)、[McKinsey 的分组能力表](https://www.mckinsey.com/capabilities/tech-and-ai/our-insights/rewired-to-outcompete)、[BCG 的阶段与角色对齐](https://web-assets.bcg.com/img-src/BCG-Are-You-Ready-to-Transform-Jan-2020_tcm9-236329.pdf#page=2) 和 [Digital.gov 的服务蓝图](https://digital.gov/guides/research-collaboration/user-needs/journeys)。抽取阅读机制后，按活动参考的版面语言重新绘制。
