# 按用途检查组件覆盖

在扫描参考前，用一句话写清设计包的用途，并列出该用途里反复出现的内容关系。优先检查会影响理解或决策的关系。参考稿里具有辨识度的构图、素材和局部细节也要纳入提取。

从[标准组件库](component-library.md)查看各组件的内容约定及复用状态。按用途选择本次需要的组件，并用目标风格的参考证据确定具体实现。

## 起始组件约定

以下两项适用于内部机制说明和推进评审。沿用相同的语义字段和关系，具体形状、色彩、字阶、构图与槽位容量由参考证据和目标媒介决定。

| 关系 | 页面字段 | 每项字段与数量 | 读者要看懂的关系 |
| --- | --- | --- | --- |
| 双向反馈闭环 `feedback-loop` | `kicker`、`folio`、`title`、`setup`、`loop-label` | 两项，每项 `party`、`mechanism`、`flow`、`constraint` | 第一方的流指向第二方，第二方的流指回第一方。标出共同结果，分别交代各方的局限。 |
| 三阶段行动与验收 `action-checkpoints` | `kicker`、`folio`、`title`、`decision` | 三项，每项 `milestone`、`action-label`、`action`、`check-label`、`check` | 按稿件顺序排列阶段，把每项行动和它的验收条件放在同一组。 |

已有包的语义契约继续由原配方维护。针对本次用途缺少的关系，在工作副本中按以上约定或本次内容需求补齐。

三阶段行动与验收适用于稿件明确给出阶段行动和验收条件的情况。若同页汇集即时行动、里程碑与独立度量，保留这些分组，用对应关系的配方组合内容。把独立的验收字段作为稿件输入要求。

## 从覆盖缺口到可调用版式

1. 分别记录素材证据与它在页面里的作用。PPTX 按对象 ID 导出原媒体，原件可按哈希去重，每次出现的裁切、位置和组合关系分别保留。PDF 按页核对图像对象及原图流，标清掩码、裁切和渲染衍生件。截图可据可见形状、层级和组合重建，独立原件、原字体身份及图层以取得的证据为准。把素材标为版式承载、装饰、可替换内容或仅作证据，并写清它跟随页面、组件还是内容槽。
2. 用固定的中性稿严格匹配原包，保留编译报告和原包。在 `STYLE.md` 里逐项记录目标组件、字段和容量、原包结果、来源地址、补足决策、配方以及验证范围。用下表判断组件进度。素材可独立导出的状态另由目录和资产清单记录。
3. 为缺失且高频的关系先重组已确认的对齐轴、字体层级、色彩角色和部件。遇到原包缺少的流程、层级或循环，按[标准结构与风格映射](structural-components.md)补足。新增元素沿用 `extended` 标记，分别说明继承的风格证据和补入的结构。测试稿与编译报告留在包外。
4. 同一组件需要进入两种构图时，优先复用一组内容槽、图层关系与样式定义，再分别安排页面区域和标题。HTML 版式可引用[带文字槽的共享图形](reproducibility.md#工具与边界)，在生成时填入各自的槽位。配方及 `variant` 仍负责选择整页版式。
5. 冻结候选设计包，从重新解压的 ZIP 重跑原中性稿和第二份同关系稿。核对箭头方向、阶段顺序、原文与槽位、中文断行和视觉层级。用一个超出已知容量的例子核对缺口报告。分别记录配方的字符上限和实际通过视觉检查的内容长度，范围以实际验证过的构图和媒介为准。

| 组件进度 | 判定依据 |
| --- | --- |
| 可直接调用 | 原包配方匹配关系、字段和容量，实际填槽与版式通过验证。 |
| 可改造现有结构 | 来源或原包已有对应关系，补充或重绑字段即可满足需求。标明可独立调用的部分及整页绑定。 |
| 需按风格延展 | 参考提供可继承的规则或部件，目标关系需要新增分组、连接或内容层级。 |
| 待验证 | 证据、实现或验证仍有缺口。记录影响和适用边界。 |

跨来源格式或风格比较时，先用同一份语义稿运行各原包，保留直接匹配及缺口。用各自证据完成的工作副本再跑同一份稿。记录复用的内容槽和每套风格各自的视觉规则，并逐页核对原文、顺序及组件关系。
