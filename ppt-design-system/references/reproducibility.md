# 设计语言复现

用于需要交接给另一设计师、模型或渲染器复用的任务。输出由同一套证据派生的 `STYLE.md` 和 `design-system.json`。前者解释设计判断，后者锁定可重放的色彩、字体阶、圆角、描边、页面槽位和共享图形。以机器包和实际渲染验收复现。

## 选取并批准设计语言

1. 把参考稿缩到同一尺度，按画布、字体层级、主轴、图片语法和跨页重复关系分组。先选一个主风格家族，登记支持家族的用途、排除家族及页码。未覆盖的页面保持未分类。每个具有辨识度的规则用代表页及一个对照页核对。出现不同风格时，以目标任务和所选家族的证据为依据。
2. 记录每条规则的来源页和区域。能读取 PPTX 原生对象时附对象 ID。将设计事实、视觉归纳与延展标开。实测值只在对应样本范围内成立；移植值、替代字体和新组件标成延展。若原稿无法支持关键身份规则，`STYLE.md` 中列为待确认，等有依据再冻结。
3. 将视觉判断落成可执行的关系。记录共同上沿、图文面积和留白方向，区分颜色在画布、标题、标签和图片内的职责。图片规则应包含角色、主体与留字区、裁切、色彩或光线以及可替换条件。说明哪些素材可作为源对象保留，哪些只迁移其处理方法。
4. 只将通过设计评审的规则编入机器包。颜色、字阶、圆角、描边各自绑定规则 ID。每个版式记录所服务的页面任务、所用家族和规则。带判断空间的地方可提供多个已评审版式，由模型在其中选择。新增构图先按延展登记，补证据与评审，再加入候选。机器包版本变更应保留旧包，重跑受影响的样本。

## 复现与评审

- **单页**　把新内容映射到已评审槽位。需要照片时先对比原稿与替换素材的主体位置、比例和留字区，再选择裁切。检查长标题、长正文、CJK 与拉丁混排的实际成像。
- **多页**　按同一故事职责逐页选版式。将同一个回扣图形定义为 `motif`，使用同一组元素重放。缩小、放大或改变高亮由批准的版式控制。关键顺序定义在 `sequences` 中，每步列出允许版式及焦点、密度和视觉强度。
- **换素材评审**　使用新素材与重绘形状，将原稿和输出并排审视。判断新稿是否仍保有相同的视觉语言、主题焦点是否压过装饰、遮住品牌与原素材后能否读出一致的构图逻辑。发现只靠原素材成立时，回到素材角色和关系规则重做。
- **保留原稿背景**　交付要求保真时，在风格家族的 `backdrop` 中登记已批准的 16:9 背景文件、SHA-256 和来源证据 ID。单独导出原稿的背景图层，输出时放在全部新内容下面。换素材评审单独使用重绘背景的设计包。
- **跨模型评审**　冻结机器包、故事职责、内容、素材条件和渲染环境。由各模型独立提交版式 ID 和槽位。同一方案的相同输入要求重复出图一致。不同批准方案可以有不同构图，分别检查焦点、阅读顺序和同族辨识度。两种比较分开报告，独立设计评审结束后再声明跨模型视觉表现。
- **双尺度验收**　先看整套缩略图的焦点变化和停顿，再按目标观看尺寸检查对比、字重、裁切、重叠与留白。叙事重要性、信息密度、实际视觉强度各自评估。标题和主图需要指向同一个关系。关键页出现错误家族、错误素材、错误阅读顺序、遮挡或出界，修复后重验。
- **局部细节验收**　对影响层级和分组的规则，在既有评审记录中串起「来源区域 → 规则 → 实际图层或文字槽 → 渲染观察」。用替换文案或改变换行复验绑定。分别记录技术检查和视觉结果。若来源无法判断或渲染器缺少对应能力，注明具体缺口，并将该项标为待确认或未复现。

## 工具与边界

[机器包 schema](design-system.schema.json) 定义了允许的字段。`patterns` 是 16:9 的有序图层，支持文字、框、线段、曲线、图片和共享图形。坐标以画布宽高的百分比表示，图层顺序决定遮挡关系。字号与圆角以容器宽度为基准，描边以 1600 × 900 参考画布定义。图层通过命名 token 取值。共享图形通过版式调整位置、尺寸和颜色映射。

共享图形可在 `motifs` 中声明文字槽。版式中的 `motif` 图层用 `box` 指定放置区域，用 `bindings` 把每个组件槽绑定到唯一的页面槽，例如 `{"party-1": "aside-party-1"}`。配方将文稿字段写入页面槽，HTML 渲染时读取映射并填入共享图形。组件的图形随放置区域缩放，绑定文字沿用幻灯片的字号。带绑定的共享图形当前支持文字、框、线段和曲线，使用当前本地 HTML 重放器。

需要保留斜放与剪贴时，用 `rotation` 设置框、短标题和图片的旋转角度。选中的原稿图片在 `fixed_assets` 登记文件、SHA-256 和单一来源图片对象，由图层引用。带原稿运行时会比对源对象中的图片字节。可替换图片仍走文稿槽位。验收时检查旋转后的边界、剪贴与文字的遮挡，以及主次重心。

`storyboard.json` 由 `version: 1` 和 `pages` 构成。每页记录 `id`、`role`、`pattern`、`focus`、`density`、`weight`、`slots`，焦点使用图层 ID。设计包声明了序列时必须传 `sequence`，逐页必须符合该序列的批准版式、焦点和强弱标注。

从仓库根目录运行。输出目录须为新目录，保留已有验收记录。

```bash
skill=ppt-design-system
python "$skill/scripts/design_replay.py" design-system.json storyboard.json \
  --source /path/to/reference.pptx --assets /path/to/replacement-assets --out /path/to/new-run
node "$skill/scripts/audit_replay.cjs" /path/to/new-run/replay.html
```

- `--source` 核对文件指纹、页数及提供的 PPTX 对象号。对 PPTX 换素材，还会拦截与原稿内嵌文件字节完全相同的图片。压缩后副本、截图及 PDF 中图片的同源性靠素材来历与视觉对照判断。第一次冻结应传源文件。交接后可用已审核机器包直接复现，收据会标明本次是否重新核对来源。
- 图片和固定背景限定在 `--assets` 根目录，离线嵌入。输出 `receipt.json` 记录设计包、分镜、渲染代码、HTML 和使用素材的 SHA-256，以及实际使用的原稿背景。浏览器检查使用本地 Playwright 与 Chromium，可通过 `REPLAY_PLAYWRIGHT_PACKAGE` 和 `REPLAY_CHROMIUM` 指定安装路径。
- 自动检查覆盖来源地址、允许的家族和版式、字段、图层边界、槽位、顺序，以及 Chromium 中的文字碰撞、溢出和图像加载。浏览器报告记录版本和逐页截图指纹。同环境截图对比可检查重放一致性。字体文件、操作系统、浏览器版本和输出媒介改变时，重新验收。第一眼落点、证据是否支持设计推断、换图后的家族辨识度由设计评审决定。
- 此命令接受经评审的机器包，输出 HTML 视觉样稿。网页快照、图片与 PDF 的视觉证据按[提取指南](style-guide.md)采集。
