# Select imagery and direction when only a style is named

**English** | [简体中文](style-selection.md)

Use this entry for “Death Stranding-inspired,” “L’Oréal Groupe style,” or “lively editorial design” without a concrete reference, specification or approved pack. It precedes existing Extract / Reuse / Make. Style-description production uses the [reference preflight](style-preflight.en.md); it adds no pack field or production mode.

Reuse a supplied file, URL, pack or current approved direction. Approved reuse must trace to a user choice applicable to this task; a pack discovered in a cache or remembered as successful is not approved by its existence. Replacing copy, adding a page or missing one image does not restart the whole selection. An explicit delegation to choose or skip selection permits a recorded agent decision **after reference research**; it does not waive research. “Start” alone skips neither choice. Silence, preselected options and elapsed time are not answers. Resolve identity ambiguity briefly when the brand/group/work distinction would change the reference.

Do not exempt familiar or visually distinctive names: a recognizable film name is still a style-description input until concrete references or applicable approved reuse are established. Distinguish three permissions: prior-material reuse, who selects the direction, and whether reference research may be skipped. Do not infer one from another. “Do not use past memories/packs/assets” prohibits those inputs, not fresh image search. Generated backgrounds, procedural drawing and typography-led graphics describe production techniques; none substitutes for reference research.

## Choice 1: image approach

For a named brand/IP with meaningful cover, transition or content imagery, ask first unless explicit prior choices already apply. Independent reference research can proceed while awaiting the answer; image-bearing candidate production waits for it.

> How should the images be handled?
>
> - Use images from the named brand/IP, such as official stills, environments or product photos.
> - Use independent images with similar light, materials or composition, such as suitable photography or original art.

Naming an IP style does not choose original images. Similar-style does not automatically mean AI generation: decide reuse/search/original extension using [image roles](image-roles.en.md) and [sourcing rules](photo-sourcing.en.md). If typography, fields and structure fulfill the page without imagery, record “not applicable” and proceed to direction selection. Generic non-IP descriptions need no imaginary IP-image question.

The image approach can be scoped by role/page, such as official cover imagery and independent content images. Separate observing original references from placing their images in a deliverable. Independent-assets production still studies suitable references; candidates/results follow the selected asset approach. Keep source/distribution conditions under existing asset rules; a user choice does not expand rights. Similar images cannot substitute for evidence of a specified person, product, place or event.

## Choice 2: select a visible visual direction

1. **Inspect actual references first.** Search/view suitable official sites, public reports, presentations or reliable references, even for independent or generated output assets. Generic styles can explore different visual families; brands/IP can use different media, periods or page roles. Retain links, image files, regions and observations. A search snippet, navigation-only page or unviewed URL does not count as visual evidence. If one source fails, try another suitable source. If references remain inaccessible, report the gap; do not enter full production unless the user explicitly waives reference research. Then label the work an original proposal, not an observed reconstruction. Do not reinterpret an earlier selection delegation as that waiver.
2. **Usually offer 2–3 distinct candidates.** Differences should involve type hierarchy, composition, image treatment, density or graphic rhythm, not just primary color, corner radii or the original photo. All candidates respect the chosen image approach so the choices remain separate.
3. **Render identical sample copy.** Usually make a cover and representative content page per candidate. If the manuscript has data, prefer the same data page; otherwise do not invent numbers. Preserve copy, facts and data while varying grouping, whitespace, composition and density. Without confirmed copy, use the same explicitly labeled placeholders. Reuse existing rendering, without producing the full deck early. Check readability, fit and crops. Distinguish source evidence from generated previews; names/descriptions or source screenshots alone are not rendered candidates.
4. **Present and wait for selection.** Show source evidence, actual previews, short differences and trade-offs, then ask which direction to use. A simple comparison image/offline page is enough; do not build a new selection app unnecessarily. A recommendation is not a user choice. While waiting, organize copy/sources, but do not freeze a direction's formal pack or make the full deck.
5. **Allow combinations with explicit scope.** For example: A overall, B only for data pages. If the user selects A+B without defining scope, propose a concrete hierarchy based on the shown differences and state it; ask again only when ambiguity materially changes the design. Carry the decision forward in the project. Change direction in a production copy while retaining the original pack.

Possible presentation structure; derive the actual directions from current observations rather than always using these names:

| Direction | Actual source evidence | Same-copy rendered previews | Differences/trade-offs |
| --- | --- | --- | --- |
| A · Editorial | Viewed cover/content regions | Cover + content | Title, whitespace, field rhythm and long-copy fit |
| B · Metric-led | Viewed report/presentation exhibit | Same cover copy + same content/data | Number hierarchy, charts and annotation density |
| C · Image-led, if supported | Viewed image/text pages | Same content and selected image approach | Image proportion, crop and chapter transitions |

## Record the decision and resume the workflow

In existing production records or `style-selection.md`, retain the following. This is an agent decision record, not a new compiler input format.

- Original request, known use and specific entity.
- Image approach: direct / independent similar-style / scoped mixture / not applicable; pages and user-choice basis.
- Candidate IDs, source links/viewed regions, preview locations and known unreplicated details.
- User's selection or explicit delegation; primary direction and scoped secondary direction.
- Sources subsequently used by Extract, inherited features, extensions and unknowns.

After selection, build/reuse a source-backed pack, replay and freeze its baseline, then adapt new copy in production. Candidate previews are production proposals; do not treat them as evidence that the original source contained those layouts. Existing typography, title-backdrop, color-field, image-role and editability checks remain unchanged.
