# 从参考稿元素到新稿页面

## 1. 提取元素目录

先按视觉家族检查代表页，再对原稿逐页编号。记录对象 ID、位置、父组和层级。为可读取的属性生成去重 token，包括色彩、字体和字阶、间距、形状与圆角、填充与渐变、描边、效果、图片指纹和裁切。原生背景和装饰背景分别记录。保留图标的形状和素材引用，由设计判断补充含义。图片内已经栅格化的细节标为观察或待确认。

PPTX 可以直接运行底层扫描。它保留对象和媒体定位，扫描结果可据此在本机原稿提取被选中的素材。组内坐标应结合父组变换阅读。PDF、图片和网页按[格式证据](style-guide.md)采集可观察的 token 与出处。

检查小而有辨识度的图片与图标，例如章节高光、步骤图标、角标与裁切主体。对可单独复用的素材，在 `assets/` 保存原件及所需的渲染衍生件，并在元素目录记录来源页、对象或包内位置、文件指纹、视觉角色、语义及替换条件。通用高光可以固定，步骤图标按动作选择；人物、产品或平台标识按其内容语境处理。需要用到母版或版式对象时，元素目录保留其作用域地址，并在设计系统证据中通过 `catalog_refs` 绑定到可见页。

### 筛选可复用素材

对照代表页与源对象，先写清候选素材在页面中的职责，以及换一份文稿后它还能承担什么作用。依据包的使用范围选择保留方式。出现次数只是线索，一次出现的横向高光也可以是转场的关键元素。

截图里看起来像图片的区域，先按[图像职责](image-roles.md)判断它是否依赖真实照片、可重建的视觉语言或实际数据。需要表达新的内容关系时，图像选择与版式延展可以同时进行。

- **保留原件。** 原件的轮廓、光泽或品牌特征对该页型有明确作用时，保留原件，并注明适用页型和调用条件。组合装饰依赖叠层时，可同时交付去掉文案的渲染衍生件，例如玻璃卡面。
- **保留替换槽。** 人物、产品照或数据图随主题变化时，定义槽位的职责、主体落点、裁切和叠放要求。同一产品系列的专用包可根据复用范围保留特定产品图。
- **记录为证据。** 用途、独立性或来源暂不明确时，记录代表页和观察，待有明确用法再纳入可调用素材。

用现有元素目录记录证据和视觉职责，用语法的 `use` 和版式槽位记录调用或替换条件。用换稿复核固定素材仍有作用、替换后的图像仍能维持构图。

使用已有设计包或做版式延展时，复核拟继承的视觉职责在实际成稿中的落点。纸片、回形针、剪贴等会改变分组、层次或焦点时，追到原件、实际使用的版式图层与截图；素材清单只证明可调用。纸片与标签等源图已按比例拉伸的装饰，可用 `fit: fill` 直接按版式框显示原件。人物和产品图片沿用保持主体比例的裁切规则。

对于版式承诺保留的固定 PPTX 前景原件，在 `required_fixed_assets` 登记图层、素材和视觉职责。根据各页型和变体选择必要原件，例如双栏各自的承载纸片。情绪剪贴等素材按本页任务选用。保留源页对照，并在重放后检查遮挡、前后关系和第一眼落点。[配置与验收](reproducibility.md#固定原件验收)

## 2. 编译使用规则

从目录选择可复用元素。每项登记 `kind`、`family`、`objects`、`tokens`、`relations`、`use`、`status`。用 `change` 说明延展如何调整。图标写清指向和语义。照片记录主体、裁切和前后层。背景用家族固定底层。卡片记录适用的内容关系、允许容量、标题与说明的层级及边界。

在定配方前按[整页构图规则](page-composition.md)完成整页观察。把规则挂到对应的页面职责，写明哪些布局关系和图片用法来自原稿，哪些为新内容而延展。

配方 `recipes` 将章节关系和可选 `variant` 绑定到设计包中的 `pattern`。每个图层可追到已评审元素。用 `fields`、`items` 和 `limits` 分配内容槽与容量。`layout` 写明第一眼落点、主次位置关系、对齐与偏移、图片任务或省略条件，并在 `pattern` 中实际落实。数字上限用于初筛，文字成像由浏览器检查。设计包负责实际位置、颜色、字阶及共享图形。

## 3. 读稿、匹配和延展

生产复用的输入是原文与设计包，输出是独立的 `storyboard.json` 和 `compile-report.json`。设计包中的 `STYLE.md` 供人和 AI 理解设计语言，`element-catalog.json` 记录证据，`style-grammar.json` 管匹配，`design-system.json` 管渲染。生产用素材放在本次素材根目录，保留来源包的原始路径和指纹。

先把原文整理成章节语义。每章包含 `id`、`intent`、`relation`、`fields`、`items`，需要时加 `variant`。稿件顶层为 `version` 和 `chapters`，跨页节奏已经评审时加 `sequence`。关系来自章节要表达的判断，例如反馈闭环、同级并列、逐行对应、递进或监测。稿件保留要入页的文字及顺序，版式和图层 ID 由配方管理。

编译器按关系、变体、字段、项数、容量和序列匹配。全部章节都有唯一匹配时才写分镜。缺口报告区分没有该关系的配方、已有配方不满足约束、存在多个候选，并保留受影响的内容和可复用元素。

## 4. 设计延展

1. **定位表达缺口。** 保留首次匹配的报告，写清该页必须让读者读出的关系。区分槽位容量、候选歧义和结构缺失。容量不足先调整分组、拆页或选高密度变体。候选歧义按页面职责和原稿构图规则取舍。现有候选仍无法承载所需关系或内容时，进入延展。
2. **先重组，再补最少元素。** 在生产副本中先用现有字阶、色彩、素材、对齐和组件组织新关系。关系仍表达不全时，再补必要的图层、槽位或版式。记录继承规则及证据、重组后保留的关系、新增项及其职责、适用条件和容量。若本次改用媒体槽或拆页，记录对可编辑性和阅读顺序的影响。
3. **用第二份稿验收。** 用本次稿和另一份同关系的稿分别编译及渲染。替换关键参与方、短语或素材，检查文字适配、分组和关系是否成立。涉及流程或闭环时，同时检查方向、端点及标签归属。视觉评审在同尺度核对家族辨识度和层级，技术检查另行记录。
4. **决定去向。** 单次做法或验证不足的候选留在生产记录。通过换稿与视觉复核、适用范围清楚的候选，可以作为延展写入新版设计包。在 `design-system.json` 登记版式，在 `style-grammar.json` 登记调用规则并将新增元素标为 `extended`。沿用 `element-catalog.json` 的来源证据，新增来源时补录。在 `STYLE.md` 说明适用范围，保留原版本，并重放受影响的既有样本。可复用的旧配方继续保留。

### 示例 · 报告风格中的双飞轮

| 环节 | 实际做法 |
| --- | --- |
| 缺口 | 新稿有一页需要两侧相互回馈。既有上下色带能分别叙述两项发现，闭环关系仍需要独立结构。 |
| 重组 | 沿用参考稿的品红与金色、硬边色块、常规黑字和白底留白，把等权色面重排为左右两组，中缝给关系线。 |
| 最少新增 | 加两轮原生 SVG 轮廓、两条有向曲线和各自的流向文字槽。第一组输出走上方左→右，第二组输出走下方右→左。共同结果居中，两侧局限保留在各自色面下方。 |
| 换稿与决定 | 换成需求团队和交付团队重新编译及渲染，核对两个角色与两条流的绑定。结合原稿和中性稿的浏览器检查，以及轮廓与箭头端点检查，将 `two-wheel-feedback-loop` 登记为新版设计包的 `feedback-loop` 配方。旧色带仍服务并列发现。 |

## 运行

```bash
skill=ppt-design-system/scripts
py=python
pack=/path/to/extracted-design-pack
"$py" "$skill/compile_story.py" "$pack/design-system.json" "$pack/element-catalog.json" \
  "$pack/style-grammar.json" /path/to/manuscript.json --out /path/to/compiled
"$py" "$skill/design_replay.py" "$pack/design-system.json" /path/to/compiled/storyboard.json \
  --assets /path/to/production-assets --out /path/to/rendered
```

编译目录内的 `STYLE.md` 汇总元素、适配规则和实际渲染参数。`compile-report.json` 记录每章选择的配方、对象、源属性 token、执行 token 以及延展缺口。接着用[复现检查](reproducibility.md)核对渲染结果。章节语义和配方的审美判断均需评审，当前本地命令的自动范围为 PPTX 原生对象扫描、语义稿匹配和 HTML 重放。
