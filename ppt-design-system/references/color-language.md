# 继承颜色的职责与色场

用于参考的辨识度依赖大面积色场、明暗切换或特定颜色职责的任务。沿用 Extract → Reuse → Make，不给所有参考强制添加多彩章节。

## 提取与选型

在既有 `STYLE.md` 和规则证据中登记「来源区域 → 颜色职责 → 实际 token / 图层 → 使用条件」。除了色值，记录它是整页底色、章节色场、内容承载面、文字、行动、状态还是图片内部的颜色；哪些页型使用、出现在哪里、占据多大范围，以及跨页如何切换。图片内的颜色不能自动升级成品牌章节底色，动作色、Logo 色和状态色也不等于通用装饰色。

用代表页和对照页区分稳定规则与偶然用色。保留来源声明、视觉实测、解释采用和生产延展的边界。按参考支持的范围选择浅色、深色或章节变体；参考本来克制时，克制就是应继承的规则。不要为了让不同参考看起来有差别而增加原稿没有的色场。

第三方 `design.md` 分析需登记作者、仓库 / URL、版本或抓取时间、文件指纹和非官方身份。可访问的官方页面用于交叉核对，不会把第三方文档变成官方规范。核对到的页面范围、未加载区域与矛盾分别写明；没有页面证据时仍可做文档驱动的适配，但不能宣称原站视觉保真。当前网页与旧文档不一致时保留两者，不静默覆盖已冻结包。

## 映射与成稿

- 将色场绑定到现有背景 token、框、组件或已批准的背景素材。只有色板而没有构图证据时，给出有限的代表页，记录本次适配；不要把自行选择的面积比例写成来源事实。
- 新稿按页面任务选择已评审变体，继承对应的色场位置和明暗节奏。长文案优先重组、分页或调整生产槽位；避免为容纳文字把大色场缩成强调线，或把浅色正文页全部改成深色。改动登记在生产副本，冻结包保持不变。
- 同时看整套缩略图和阅读尺寸，检查色场是否真正出现、位置是否保留、文字对比和状态含义是否正确。字体比例、信息密度与素材职责仍按各自规则验收，不能用明显配色代替这些判断。
- 对易漂移的平涂色场，可登记本次审阅通过的区域和覆盖区间，运行下方检查。像素检查只能发现可观察的颜色面积变化；不能代替语义、审美或跨页节奏评审。原生 PPTX 另核对底色 / 填充 / 文字，再按目标环境验收。

## 实际截图色场检查

`check_color_fields.py` 接受独立的生产评审 JSON，不改变设计包 schema。截图须为实际渲染的单页画布，去掉编辑器工具栏；路径相对于评审文件。`region` 是归一化 `[左, 上, 右, 下]`，默认全页；覆盖率的分母是选定区域。`tolerance` 是 RGB 各通道允许误差，默认 3。`min_fraction` / `max_fraction` 必须由参考或已审阅适配支持，没有统一品牌占比阈值。

下面的数值仅演示本次适配如何验收，不是品牌规则：

```json
{
  "pages": [{
    "id": "cover",
    "screenshot": "renders/cover.png",
    "fields": [{
      "role": "chapter-field",
      "color": "#FFE01B",
      "region": [0, 0, 1, 1],
      "min_fraction": 0.75,
      "max_fraction": 1,
      "evidence": "source.md: chapter color; official hero screenshot",
      "basis": "本次已审阅的整页色场适配，允许标题和正文覆盖"
    }]
  }]
}
```

```bash
python ppt-design-system/scripts/check_color_fields.py color-review.json --out color-report.json
```

报告逐项写实际覆盖率、预期区间、区域、来源说明、截图 SHA-256 与通过状态。空清单、非法范围、缺少依据或截图无法读取会拒绝；超出覆盖区间时返回非零退出码。局部色场用 `region` 限定位置，避免别处的同色元素补足总面积。对渐变、透明叠色、照片和纹理，不使用单一 HEX 比例验收；保留实际截图并做区域视觉对照。不要通过扩大容差或放宽区间掩盖未审阅的漂移。
